# 经验库

Usus 的经验正文。一条经验一个 Markdown 文件，长期维护、纳入 git。模块只读这里、在运行区建索引，不往这里写缓存。

## 放哪

- 按大类分子文件夹，随用随建，例如 `连接/`、`传动/`、`结构/`、`工艺/`、`选型/`、`装配/`。
- 文件名 `<编号>-<短标题>.md`，例如 `连接/U0001-振动场合别靠弹簧垫圈防松.md`。
- 编号 `U` + 四位数字，全库唯一、只增不复用；删掉的条目编号作废。
- 本 README 和以 `_` 开头的文件不算条目。

## 条目格式

```markdown
---
id: U0001
title: 振动场合别靠弹簧垫圈防松
tags: [螺栓, 防松, 振动]
scope: 有横向振动或冲击的螺纹连接
source: 出处：手册页码、标准条款、项目编号、评审记录
date: 2026-11-03
---

正文：先一句话结论，再写为什么、怎么做、反例或边界。
需要计算的地方写 Norma 指令名（如 norma.bolt.preload），不在这里抄公式。
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✔ | 与文件名里的编号一致 |
| `title` | ✔ | 一句话结论，检索结果首先展示它 |
| `tags` | ✔ | 零件、失效模式、工艺等关键词；型号与标准号也写进来，关键词检索靠它们 |
| `scope` |  | 适用范围；不写就是通用 |
| `source` |  | 出处，能回指就写 |
| `date` | ✔ | 最后一次实质修改的日期 |

## 写法

- 一条只讲一件事。两件事就拆成两条，否则检索时会被一起捞出来或一起漏掉。
- 结论放第一句。检索片段先截开头，结论在后面就看不到了。
- 型号、标准号、数值照原样写（`HGH20CA`、`GB/T 5783`、`M8`），不要改写成描述。
